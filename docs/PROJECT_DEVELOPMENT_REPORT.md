- 安全删除已合并的本地和远程分支
- 使用提交历史进行安全回滚

需要长期牢记：

- 提交只存在于当前分支，不会自动进入 `main`
- 推送功能分支不等于主分支获得功能
- PR 合并后，本地 `main` 仍需要拉取远程最新提交
- `HEAD -> main` 表示本地当前指针位于 `main`
- `origin/main` 表示本地记录的远程主分支状态
- 工作树是同一仓库的多个检出目录，不是多个独立仓库

## 5. 主要踩坑与经验

### 5.1 Maven 不在 PATH

`mvn` 无法执行不代表 Maven 没有安装。应先检查 IDE 是否自带 Maven，再决定是否配置系统 `PATH`。

### 5.2 CMD 与 PowerShell 语法不同

CMD：

```cmd
set DB_PASSWORD=你的密码
```

PowerShell：

```powershell
$env:DB_PASSWORD="你的密码"
```

不能在 CMD 中直接使用 `$env:` 语法。

### 5.3 端口 8080 被占用

通常是旧后端仍在运行。修改代码不一定需要停止服务，但重新启动前应确认没有旧进程占用端口。

### 5.4 Git 首次提交文件很多是正常现象

项目初始化 Git 后，原有源码都会显示为未跟踪文件。这不表示这些文件都是当前 Day 新写的，而是 Git 第一次开始记录它们。

### 5.5 配置或后端接口修改后必须重启

新增 Controller 接口、修改 Spring Security、切换模型或设置环境变量后，仅刷新前端不会生效，必须重启后端。

### 5.6 403 不一定只是权限配置错误

可能原因包括：

- JWT 已过期
- 前端残留旧登录状态
- 用户角色不匹配
- 流式请求进入 Spring `ASYNC` 分发后再次被安全过滤器拦截

### 5.7 Vue 深层状态必须确认响应式

流式回答曾在后台持续生成，但页面直到发送下一条消息时才一次性显示。根因是持续修改普通对象，而不是 Vue 正在渲染的响应式消息对象。

### 5.8 推荐检索不能直接使用整句 SQL LIKE

`%胃口不好怎么办%` 很难命中文章。推荐功能应使用关键词提取、主题评分、全文检索或向量检索。

### 5.9 模型可用不等于适合当前项目

`glm-5` 在当前 DashScope 兼容接口中多次读取超时，而 `qwen-plus` 更稳定。模型选择需要同时考虑：

- 账号权限
- 免费额度
- 模型区域
- 接口兼容性
- 首字延迟
- 总响应时间

### 5.10 API Key 不应出现在截图

开发过程中 API Key 曾出现在终端截图。该 Key 应在云平台控制台撤销并重新生成。今后必须遮挡密钥，不得写入：

- 源码
- `application.yml`
- Git 提交
- 日志
- 截图
- PR 描述

### 5.11 大范围 UI 改造容易偏离预期

药膳页面曾因一次修改范围过大而回滚。后续页面优化应：

- 先保留现有结构
- 根据用户指出的位置局部修改
- 重大布局变化先输出方案
- 一次只验证一个视觉方向

### 5.12 不应连续叠加猜测性补丁

流式输出问题经过多次表象调整后，最终通过状态数据流定位到响应式对象问题。以后遇到复杂 Bug，应先复现、记录现象、检查数据边界，再修改代码。
