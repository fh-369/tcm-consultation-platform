阶段目标：

- 从患者端体验优化切换到后台管理体验完善。
- 区分管理员和医生的实际工作场景。
- 让后台页面从“功能可用”升级为“角色清晰、入口直观、能支撑业务流程”。

完成内容：

- 重新设计后台管理布局、侧边栏、数据概览和卡片风格。
- 支持后台侧边栏展开与收起。
- 去除正式页面中偏测试或解释性质的文字。
- 统一后台搜索、筛选、表格和操作按钮视觉。
- 实现管理员查看用户、医生列表及账号状态。
- 建立医生入驻申请页面，普通用户可以提交医生申请。
- 管理员可以审核医生申请，并管理医生状态。
- 建立科室主数据，为后续科室分诊和多医生分配做基础。

关键经验：

- 管理员和医生不应该看到完全相同的后台。
- 管理员更关注平台运营、人员、内容和调度。
- 医生更关注自己能处理的问诊和自己已接手的问诊。
- 页面说明文字在开发阶段有帮助，但正式页面应尽量减少“解释型废话”。

### 3.10 2026 年 6 月 20 日至 21 日：科室分诊与医生工作台拆分

阶段目标：

- 将“所有医生看所有问诊”的模型，升级为更接近真实业务的科室分诊模型。
- 将医生页面从管理员调度中拆出，形成医生自己的工作台。

完成内容：

- 用户提交问诊单时选择问诊科室。
- 旧问诊统一归入“综合咨询”。
- 管理员可以修改问诊科室。
- 医生端增加“科室问诊池”。
- 医生端增加“我的问诊”。
- 科室问诊池只用于查看和认领，不在这里填写回复。
- 认领后的问诊进入医生“我的问诊”处理。
- 综合咨询与本科室问诊池共同构成医生可认领范围。

设计取舍：

- 暂不实现排班日历和复杂排班功能。
- 暂不实现医生一注册就自动执业，医生入驻必须经过管理员审核。
- 暂不让普通用户注册时直接成为医生。

### 3.11 2026 年 6 月 21 日：管理员调度与自动分配

阶段目标：

- 管理员可以从全局视角调度问诊。
- 系统可以根据科室和医生负载进行初步自动分配。

完成内容：

- 管理员问诊调度支持按科室、医生、状态、紧急度筛选。
- 管理员支持跨科室转诊和重新分配医生。
- 自动分配根据科室、账号启用状态、医生审核状态和未完成数量选择医生。
- 医生主动认领后，管理员页面可以看到分配和状态变化。
- 医生页面和管理员页面的搜索筛选组件进一步统一。

关键经验：

- 自动分配不是替代管理员，而是减少普通问诊的手工分派成本。
- 复杂排班、工作时间、医生休假等功能会显著增加系统复杂度，适合后续版本再做。

### 3.12 2026 年 6 月 21 日至 22 日：问诊处理流程与医患沟通

阶段目标：

- 完成从用户提交问诊，到医生接诊、回复、更新状态，再到用户查看结果的闭环。
- 避免“医生回复一多，用户卡片无限拉长”的体验问题。

完成内容：

- 医生在“我的问诊”中处理自己负责的问诊。
- 医生可以填写回复并更新状态。
- 患者端“我的问诊”中只展示简要处理进度。
- 患者可以展开查看详细医生回复。
- 在医生未结束问诊前，患者可以继续补充回复。
- 去除了原计划中的随访时间、随访记录业务，避免流程过重。

关键经验：

- 用户端问诊列表不适合直接展示大量医生回复。
- 列表页适合摘要，详细沟通适合折叠展开或进入详情。

### 3.14 2026 年 6 月 23 日：AI 对话数据库持久化

阶段目标：

- 将 AI 对话从浏览器本地存储升级为数据库持久化。
- 避免刷新、换浏览器、清理缓存后对话丢失。
- 让删除对话可以真正删除数据库记录。

完成内容：

- 新增 `ai_conversations`、`ai_messages`、`ai_conversation_recommendations` 三类数据模型。
- 新增 AI 对话、消息和推荐快照相关 Mapper、DTO 和 Service。
- 前端从 localStorage 为主，升级为数据库为主。
- localStorage 只用于旧本地对话的一次性迁移。
- 对话列表分页加载。
- 消息按最近消息分页加载，不一次性拉取全部历史。
- AI 请求只携带最近若干轮和预留历史摘要，不把全部历史发给模型。
- 删除对话时物理删除对应对话、消息和推荐快照。
- 每个对话首次提问时，结合首次问题和所选问诊单生成 1 到 4 篇站内延伸阅读推荐。
- 后续同一对话继续沟通时保留首次推荐，不重复变化。
- 站内延伸阅读默认折叠，用户需要时再展开。

当前限制：

- 历史摘要字段已经预留，但还没有自动摘要生成。
- 推荐仍以关键词匹配为主，后续可以升级为全文检索或向量检索。
- AI 联网搜索尚未实现。

## 5. 主要踩坑与经验

### 5.1 Maven 不在 PATH

`mvn` 无法执行不代表 Maven 没有安装。应先检查 IDE 是否自带 Maven，再决定是否配置系统 `PATH`。

### 5.2 CMD 与 PowerShell 语法不同

CMD：

```cmd
set DB_PASSWORD=你的密码
```

PowerShell：

```powershell
$env:DB_PASSWORD="你的密码"
```

不能在 CMD 中直接使用 `$env:` 语法。

### 5.3 端口 8080 被占用

通常是旧后端仍在运行。修改代码不一定需要停止服务，但重新启动前应确认没有旧进程占用端口。

### 5.4 Git 首次提交文件很多是正常现象

项目初始化 Git 后，原有源码都会显示为未跟踪文件。这不表示这些文件都是当前 Day 新写的，而是 Git 第一次开始记录它们。

### 5.5 配置或后端接口修改后必须重启

新增 Controller 接口、修改 Spring Security、切换模型或设置环境变量后，仅刷新前端不会生效，必须重启后端。

### 5.6 403 不一定只是权限配置错误

可能原因包括：

- JWT 已过期
- 前端残留旧登录状态
- 用户角色不匹配
- 流式请求进入 Spring `ASYNC` 分发后再次被安全过滤器拦截

### 5.7 Vue 深层状态必须确认响应式

流式回答曾在后台持续生成，但页面直到发送下一条消息时才一次性显示。根因是持续修改普通对象，而不是 Vue 正在渲染的响应式消息对象。

### 5.8 推荐检索不能直接使用整句 SQL LIKE

`%胃口不好怎么办%` 很难命中文章。推荐功能应使用关键词提取、主题评分、全文检索或向量检索。

### 5.9 模型可用不等于适合当前项目

`glm-5` 在当前 DashScope 兼容接口中多次读取超时，而 `qwen-plus` 更稳定。模型选择需要同时考虑：

- 账号权限
- 免费额度
- 模型区域
- 接口兼容性
- 首字延迟
- 总响应时间

### 5.10 API Key 不应出现在截图

开发过程中 API Key 曾出现在终端截图。该 Key 应在云平台控制台撤销并重新生成。今后必须遮挡密钥，不得写入：

- 源码
- `application.yml`
- Git 提交
- 日志
- 截图
- PR 描述

### 5.11 大范围 UI 改造容易偏离预期

药膳页面曾因一次修改范围过大而回滚。后续页面优化应：

- 先保留现有结构
- 根据用户指出的位置局部修改
- 重大布局变化先输出方案
- 一次只验证一个视觉方向

### 5.12 不应连续叠加猜测性补丁

流式输出问题经过多次表象调整后，最终通过状态数据流定位到响应式对象问题。以后遇到复杂 Bug，应先复现、记录现象、检查数据边界，再修改代码。
