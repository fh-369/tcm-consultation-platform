# 内容来源体系与产品后续路线

## 1. 文档目的

本文档记录知身问养后续内容扩充、来源追溯和产品升级的建议路线。

当前项目已经具备养生知识、药膳推荐、问诊、医生工作台、后台管理和 AI 问答等核心能力。后续如果继续扩充内容和业务，不建议只靠零散网页材料堆叠，而应建立稳定的内容骨架和可追溯来源体系。

## 2. 当前内容来源现状

当前养生知识文章主要用于项目功能验证和页面展示，内容来自零散权威网页资料与重新撰写整理，并不是照搬某一本书。

当前药膳推荐内容主要用于验证药膳列表、筛选、详情页和后台内容管理能力，部分内容属于常见食材搭配与重新整理，不是从单一书籍系统摘录。

这种方式适合早期验证功能，但后续扩展会遇到三个问题：

- 难以知道哪些主题已经覆盖，哪些主题仍缺失。
- 难以按章节体系补齐内容。
- 难以追溯每篇文章或药膳的来源依据。

## 3. 推荐内容扩充方式

后续建议采用“核心书目 + 补充标准”的方式扩充内容。

养生知识可以选择一本正式《中医养生学》规划教材作为目录骨架。先按章节建立主题清单，再逐步生成或撰写平台文章。

药膳内容可以选择一本正式《中医饮食营养学》规划教材作为目录骨架。先梳理食材、体质、季节、常见调理方向，再扩充药膳推荐。

现代营养与安全提示可以参考《中国居民膳食指南（2022）》、国家卫健委、WHO 等公开资料，用于校正饮食安全、特殊人群、慢病风险和就医提醒。

注意：不要直接复制受版权保护书籍的大段正文。应根据章节主题重新撰写，并保留来源线索，方便后续人工复核。

## 4. 建议增加的来源字段

后续如果继续完善数据库，建议给养生文章和药膳推荐增加来源字段。

建议字段如下：

| 字段 | 说明 |
| --- | --- |
| 来源类型 | 书籍、指南、网页、课程讲义、原创整理等 |
| 书名 | 如果来源是书籍，记录书名 |
| 作者 | 书籍作者、主编或机构 |
| 出版社 | 书籍出版社 |
| 版本 | 版次或出版年份 |
| 页码 | 内容对应页码或章节范围 |
| 来源网址 | 如果来源是网页或公开指南，记录 URL |

这些字段的目标不是让页面变复杂，而是让后台内容维护更可靠。将来可以按书籍目录统计覆盖率，知道哪些章节已有内容，哪些章节还需要补齐。

## 5. 用户端业务升级方向

用户端后续可以优先升级以下能力：

- 问诊单填写体验继续精简，支持草稿保存和常见症状模板。
- 我的问诊支持更清晰的处理时间线、医生回复展开和患者补充回复。
- AI 问答与问诊单联动，支持选择问诊单后获得更有上下文的养护建议。
- 养生知识和药膳推荐支持收藏、浏览历史和个性化推荐。
- 站内延伸阅读根据用户提问、问诊科室和症状智能推荐，而不是固定展示。

## 6. 医生端业务升级方向

医生端后续可以优先升级以下能力：

- 我的问诊加入更明确的今日待处理、接诊中、已完成分组。
- 问诊详情加入结构化医生回复模板，提高回复效率。
- 支持医生补充标签，例如脾胃、睡眠、疼痛、情志、儿童等。
- 支持医生之间转诊和管理员重新分配。
- 后续再考虑排班、工作量统计和医生个人资料展示。

当前版本已经决定暂不实现排班日历和复杂排班功能，避免系统过早复杂化。

## 7. 管理员运营能力升级方向

管理员端后续可以优先升级以下能力：

- 用户管理增加账号启用、禁用和异常账号提示。
- 医生管理增加资料编辑、审核记录和科室维护。
- 问诊调度增加按科室、医生、状态、紧急度的综合筛选。
- 内容管理增加来源字段、封面管理、草稿预览和发布前检查。
- 数据导出增加导出历史记录，避免重复导出和误操作。

## 8. AI 问答升级路线

当前 AI 问答已经从浏览器本地保存升级为数据库持久化，并支持对话、消息和站内延伸阅读推荐快照。

后续升级建议：

- 为每个对话生成历史摘要，不把全部历史消息都发送给模型。
- 将站内延伸阅读推荐算法从关键词匹配升级为向量检索或语义检索。
- 引入更严格的医疗安全提示，避免将养护建议表达成诊断或治疗。
- 支持模型配置管理，例如模型名称、超时时间和最大输出长度。
- 增加 AI 调用日志和错误统计，便于排查超时、额度、模型不可用等问题。

## 9. 数据分析、部署和安全优化

后续进入部署前，建议关注以下事项：

- 使用 Docker 或独立服务管理 MySQL、后端和前端。
- 将数据库密码、JWT 密钥、DashScope API Key 全部放入环境变量。
- 增加数据库备份和恢复演练。
- 对上传文件增加类型和大小限制。
- 对管理员接口增加更明确的权限边界。
- 对导出数据增加操作记录，避免敏感数据被随意导出。
- 前端生产构建后可以做代码拆分，降低首屏 chunk 体积。

## 10. 推荐开发优先级

建议按以下顺序继续推进：

1. 完成第 8 阶段整体验收、PR 合并和本地 main 同步。
2. 注册一个新的普通用户，验证从问诊提交到医生处理的完整闭环。
3. 补齐内容来源字段设计，但先不急着大规模录入内容。
4. 选择核心书目，建立养生知识和药膳推荐的目录清单。
5. 小批量扩充内容，每批扩充后都测试筛选、搜索、详情和 AI 推荐。
6. 再考虑 Docker 部署、域名、环境变量和生产运行配置。
