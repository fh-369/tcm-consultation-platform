# 问诊科室分诊设计说明

## 阶段位置

本阶段属于多医生体系第 2 个子阶段，建立“问诊属于哪个科室”的业务属性。它承接已经完成的科室主数据与医生准入，为后续科室问诊池、管理员跨科室调度和自动分配提供基础。

本阶段不限制医生可见范围，不拆分医生工作台，不取消主动认领，也不自动分配医生。

## 目标

- 患者新建问诊时必须选择一个启用科室。
- 不确定具体科室时可以选择“综合咨询”。
- 所有旧问诊统一迁移到“综合咨询”。
- 患者和后台人员都能看到问诊所属科室。
- 管理员可以修改未完成问诊的科室。
- 修改科室不隐式修改已分配医生。

## 数据模型

`consultations` 增加：

- `department_id BIGINT NOT NULL`
  - 外键指向 `departments.id`。
  - 建立普通索引，供后续按科室筛选与分配。

迁移顺序：

1. 先增加允许为空的 `department_id`。
2. 将全部历史问诊更新为“综合咨询”科室。
3. 再把字段改为非空。
4. 添加索引和外键。

这样可以保证现有数据不会阻断迁移。

## 患者端流程

在线问诊表单在“患者信息”之后增加独立的“问诊方向”卡片：

- 展示当前启用的科室。
- 每个科室显示名称和简短说明。
- “综合咨询”明确说明适用于暂不确定科室的情况。
- 科室为必选项，未选择时提示“请选择问诊科室”。
- 提交时只发送 `departmentId`，后端负责校验科室真实存在且已启用。

“我的问诊”卡片展示科室名称，但不改变现有问诊卡片的核心布局。

## 后台流程

问诊工作区增加：

- 表格中的“问诊科室”列。
- 详情中的问诊科室信息。
- 管理员筛选条件中的科室筛选。
- 管理员详情中的“调整问诊科室”操作。

修改规则：

- 只有管理员可以修改问诊科室。
- 已完成问诊不允许修改。
- 只能选择启用科室。
- 修改科室后保留当前 `doctor_id` 和问诊状态。
- 如果医生所属科室与问诊科室不同，页面显示“跨科室处理”提示，但本阶段不阻止操作。

医生工作区本阶段只显示问诊科室，不按科室过滤，也不提供修改入口。

## 接口变化

### 创建问诊

`POST /api/patient/consultation`

请求增加：

```json
{
  "departmentId": 2
}
```

### 问诊列表

患者和后台问诊响应增加：

```json
{
  "departmentId": 2,
  "departmentName": "中医内科"
}
```

### 管理员筛选

`GET /api/admin/consultation?departmentId=2`

医生调用同一接口时不接受该筛选控制，继续按当前权限范围查询。

### 管理员修改科室

`PUT /api/admin/consultation/{id}/department`

请求：

```json
{
  "departmentId": 3
}
```

## 后端校验

- 未选择科室：`请选择问诊科室`。
- 科室不存在或已停用：`请选择有效科室`。
- 问诊不存在：`问诊单不存在`。
- 已完成问诊修改科室：`已完成问诊不能修改科室`。
- 非管理员访问修改接口：返回 `403`。

## 兼容性

- 旧问诊全部归入“综合咨询”，不推测历史症状对应科室。
- 现有问诊分配、认领、回复和状态更新行为保持不变。
- 现有医生筛选与管理员分配逻辑保持不变。
- 科室名称通过关联查询返回，不在问诊表重复保存文本。

## 验收标准

1. 在线问诊页面能够加载启用科室。
2. 未选择科室不能提交，并看到明确提示。
3. 新问诊正确保存 `department_id`。
4. 所有旧问诊显示“综合咨询”。
5. “我的问诊”显示问诊科室。
6. 管理员列表可按科室筛选。
7. 管理员可修改未完成问诊的科室。
8. 已完成问诊不能修改科室。
9. 修改科室不会改变医生分配和问诊状态。
10. 医生可以看到问诊科室，但不能修改。
11. 后端测试、前端测试、生产构建和真实接口验证全部通过。
